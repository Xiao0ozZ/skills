# 交付总览

This file is the delivery module router. It keeps the main skill as one external tool while splitting detailed workflows into narrower modules.

Do not load every narrow module. Pick exactly one unless the user asks for a combined deliverable.

## 内部窄模块

| Narrow workflow | Use when                                                                                             | Read                           |
| --------------- | ---------------------------------------------------------------------------------------------------- | ------------------------------ |
| 需求分析与PRD        | source-stage judgment, requirement intake, scope, PRD rules, fields/statuses, acceptance/test design | `references/31-需求分析与PRD.md`    |
| 方案PPT与模板        | solution, report, PPT, master/template, screenshot page, attachment page, native PPT tables          | `references/32-方案PPT与模板.md`    |
| 会议总结与知识沉淀       | meeting notes, weekly/monthly summaries, review closeout, Obsidian capture, backlinks                | `references/33-会议总结与知识沉淀.md`   |
| 同步交接与复用         | document/source sync, handoff, reuse across contexts, workflow-improvement candidates                | `references/34-同步交接与复用.md`     |
| HTML原型与页面规范     | HTML prototype pages, page style, layout, states, prototype-only delivery                            | `references/35-HTML原型与页面规范.md` |

## 使用方式

Use this file after `00-工作模式与个人方法.md` when the user asks for a concrete artifact.

1. Confirm work mode: 快答, 工作稿 or 正式交付.
2. Pick the narrow module from the table above.
3. If external facts, files, business rules or writeback location are required, route through `10-任务路由与上下文边界.md`.
4. If the source path is missing, ask the user for the current file or folder instead of guessing.
5. Write files, Obsidian notes, formal docs, PRDs, PPTs, prototypes or skill references only after the relevant confirmation gate is satisfied. Version records and sync checks are required when any text/deck deliverable is created or modified as a file, including docs, PRDs, solution notes, PPTs, meeting notes, handoff and customer materials. Place version records after the title/cover and before the body; if there is a table of contents, place the version record before it. Ordinary quick chat drafts do not require version records.

## Quick Routing

- "写 PRD / 需求分析 / 字段状态 / 验收" -> `31`
- "做 PPT / 方案 / 汇报 / 母版 / 模板" -> `32`
- "会议纪要 / 周报 / 总结 / 复盘 / 记知识" -> `33`
- "交接 / 收口 / 同步 / 迁移复用" -> `34`
- "做原型 / 原型页 / HTML 页面 / 后台页面示意" -> `35`

## Guardrails

- Generic thinking uses the personal-method layer first; facts stay in confirmed sources.
- Business docs, PRDs and solution materials should prefer diagrams, tables and structured views when they make the content faster to understand than prose.
- Do not auto-write Obsidian, source files, standalone decision/change logs or skill files unless the current workflow explicitly allows it and the user has confirmed the write target when needed.
- Do not use workflow-agent by default.
- Do not publish, install or sync the skill from this module.
