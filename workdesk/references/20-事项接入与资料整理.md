# 事项接入与资料整理

用于 `接手资料`、`整理这些材料`、`帮我先看怎么接`、`建立工作入口`、`标准化资料`、`生成资料目录草案`。

目标是把一组材料带到“可理解、可推进、可交接”的状态，不是创建长期资料库。

## 使用方式

Use this file only when the user asks to intake, organize, standardize or make sense of a body of work.

- Default to light intake first. Create an intake summary and confirmation list; do not move files or rewrite indexes immediately.
- If the user only asks a general question, route through `10-任务路由与上下文边界.md` instead.
- Update folders, source indexes or long-term notes only after user confirmation.

## 0. 接入分级

默认先做轻接入，只有用户明确要长期维护、标准化目录、生成主入口或迁移到持续协作状态时，才进入正式接入。

| 模式 | 适用 | 输出 |
| --- | --- | --- |
| 轻接入 | 临时了解、先看资料、判断能不能接、只需回答当前问题 | 这组材料是什么、当前入口、可用资料、风险缺口、下一步；不移动文件、不写索引 |
| 正式接入 | 长期维护、多人协作、需要稳定入口和资料规则 | 入口说明草案、资料目录草案、整理建议、确认清单和必要模板 |

## 1. 默认流程

1. 先判断轻接入还是正式接入。
2. 轻接入只扫描最小必要入口，输出当前判断和缺口。
3. 正式接入再扫描用户确认的根目录，识别当前有效资料、历史资料、正式交付物、过程资料、模板、敏感资料和废弃资料。
4. 先输出整理方案，不直接移动或改写。
5. 输出关键确认点。
6. 用户确认后，再执行整理和目录更新。
7. 完成后列出未通过项、待确认项和下一步。

## 2. 草案阶段输出

- 这组材料的主题、目标、当前入口和使用场景。
- 入口文件候选：README、目录说明、主文档、表格、原型入口、代码入口、会议纪要或模板。
- 资料目录草案。
- 需要保留、归档、合并、删除或待确认的材料。
- 敏感资料和不可摘要资料。
- 需要用户确认的问题。

## 2.1 单一入口标准

资料整理优先形成一个“主入口”，可以是 README、目录说明、索引表或用户确认的现有文档。不要让 AI 默认读取多份并列索引、旧拆分索引或全目录清单。

主入口至少包含：

- 当前有效资料。
- 历史/废弃资料。
- 待确认资料。
- 敏感或只读资料。
- 关键文件的用途、状态、更新时间和使用规则。

辅助清单、文件盘点和历史目录只能作为补充，不作为默认入口。

## 2.2 资料成熟度模式

接入资料时先判断成熟度，不同模式使用不同协作方式。

| 模式 | 典型特征 | 默认工作方式 |
| --- | --- | --- |
| 成熟资料型 | 有主文档、已确认规则、版本记录、模板或稳定入口 | 以当前有效资料为准，重点做差异、同步和交付。 |
| 资料恢复型 | 来自评审、投标、可研、方案、会议、客户回复，缺少统一口径 | 先恢复事实和资料阶段，回答必须标依据，不把承诺或规划说成已实现。 |
| 实现优先型 | 代码、接口、部署、任务台账更完整，说明文档不足 | 先读真实实现和技术文档，输出实现现状、差异和补文档建议。 |
| 临时材料型 | 只有零散文件、截图或单次材料 | 只做本轮分析和整理建议，不建立长期规则，除非用户确认。 |

如果处于资料恢复型，草案要额外列出：正式资料、评审资料、商务资料、需求资料、过程资料、敏感资料，以及哪些资料默认只读。

## 3. 目录归类

常见目录类型：

- 当前有效资料区
- 正式交付物区
- 会议和过程记录区
- 历史归档区
- 模板和资产区
- 敏感资料区
- 待确认区
- 废弃或重复资料区

默认原则：

- 当前有效资料必须容易找到。
- 历史资料不能混在当前规则里。
- 敏感资料只识别和标注，不输出内容摘要。
- 目录用途不明时，保留原位置并列确认项，不强移。
- 文件名可读性差时，先列重命名建议，不直接改。

## 4. 执行前必须确认

在移动文件、更新目录、改主入口或写 Obsidian 前，至少确认：

- 当前有效入口是哪一个。
- 哪些资料是历史、废弃或只读。
- 是否允许移动、重命名、合并或删除。
- 是否有敏感资料和不可摘要内容。
- 是否需要长期维护入口。
- 是否现在更新目录说明。

## 5. 确认后执行

确认后再做：

- 执行移动或重命名计划。
- 更新主入口或资料目录。
- 标注历史、废弃、敏感和待确认资料。
- 生成交接说明。
- 列出未完成项和下次入口。

## 6. 完成标准

只有满足以下条件，才算接入完成：

- 已确认当前有效入口。
- 已区分当前、历史、待确认和敏感资料。
- 已说明哪些内容未确认。
- 已给出下一步最小动作。
- 如需落文件，已按用户确认的位置写入。
