## 1. 什么时候用

用户说“先做原型”“出一版 HTML 页面”“做后台页面示意”“只做原型页不接接口”时，默认走本模块。

先判断是不是只做页面表达：

- 只做原型页：重点是页面结构、字段、按钮、状态、弹窗和流程表达。
- 原型 + PRD：页面表达和规则说明都要有，不能只有图。
- 真实前端：进入真实代码、组件、接口和样式体系，不再把 HTML 原型当最终交付。

### 1.1 原型交付级别

默认按下面三档判断，不要一上来过度实现：

| 级别 | 适用场景 | 最低要求 |
| --- | --- | --- |
| 页面示意 | 先验证方向、入口和区块结构 | 页面骨架、核心字段、关键按钮、主状态 |
| 可评审原型 | 需要评审流程、规则、异常和权限 | 页面骨架 + 弹窗 + 状态 + 校验 + 示例数据 |
| 可交底原型 | 需要支撑 PRD、开发交底或演示 | 可评审原型 + 页面说明 + 同步项 |

没有明确要求时，默认做到“可评审原型”，不要做成假实现。

## 2. 统一页面骨架

未来新场景如果没有单独品牌规范，HTML 原型默认沿用这一套后台产品骨架，保持你个人输出风格统一。

1. 桌面后台优先，默认左侧导航 + 顶部栏 + 主内容区。
2. 左侧导航宽度稳定，一级导航清晰分组，当前页高亮明显。
3. 顶部栏只放面包屑、返回、提醒、账号或少量全局动作，不堆业务按钮。
4. 主内容区按“页面说明区 -> 筛选/操作区 -> 主模块区”展开。
5. 页面主体用白底卡片承载，卡片层级不要过深；一屏内优先 1 到 3 个主模块。
6. 列表页先有筛选，再有表格，再有批量操作或分页。
7. 详情页先给摘要信息，再给明细模块、记录、时间线或附件。
8. 表单页按信息块分组；长表单优先弹窗分段或双栏，不做一整页杂糅输入。

### 2.1 前端基线与视觉语言

从现有原型页抽出来的统一基线：

- 默认技术栈：静态 HTML + Vue 3 + Element Plus + Tailwind 风格工具类 + Element Plus Icons，用于快速表达页面，不默认接真实接口。
- 文件形态：优先单文件 HTML，通过 CDN 引入依赖；除非用户明确要求真实工程，不新建复杂前端工程。
- 字体：`Inter` + 系统无衬线回退。
- 页面底色：浅灰背景；内容模块以白底为主。
- 主品牌色：蓝色系，默认可用 `#00689E` 作为导航和主按钮主色。
- 状态色只按语义用：成功绿色、警告橙色、危险红色、处理中/主操作蓝色、禁用灰色。
- 圆角、阴影、边框保持克制：以 `rounded-lg` / `rounded-xl`、细边框、轻阴影为主。
- 信息密度偏管理后台，不做营销页、装饰大图、漂浮卡片墙或过强动效。

页面层级固定：

1. 左侧导航：模块分组、当前页高亮。
2. 顶栏：左侧放面包屑；右侧默认放统一账号下拉，即头像 + `Admin` + `退出登录`。
3. 页面标题区：放在 `main` 的第一块，包含标题、子标题和页面级主操作。
4. 内容区：摘要卡、筛选区、表格、看板、详情、配置块、日志等。

不要把页面标题、子标题和页面级主按钮放进顶栏。顶栏不是页面正文区。
后台页右上角不要默认做成通知/刷新按钮组；通知、刷新等动作需要时放到页面标题区、筛选区或具体模块里。

### 2.1.1 组件选型

默认组件使用规则：

| 交互/内容 | 首选组件 |
| --- | --- |
| 主按钮、次级按钮、危险操作 | `el-button`，主操作用 `type="primary"` + `color="#00689E"`，次级用 `plain` 或 `link` |
| 文本输入、搜索、数字输入 | `el-input`、`el-input-number` |
| 单选、多选、开关 | `el-radio-group`、`el-checkbox-group`、`el-switch` |
| 下拉、级联、日期 | `el-select`、`el-cascader`、`el-date-picker` |
| 标签和状态 | `el-tag`、`el-badge`，状态色按语义，不随意换色 |
| 列表和数据表 | `el-table` + `el-table-column`，少列不默认固定列；表格外层保持稳定宽度 |
| 分页 | `el-pagination` |
| 页面分组 | Tailwind grid/flex + 白底边框模块，不嵌套多层卡片 |
| 详情信息 | `el-descriptions`、摘要卡、分组字段块 |
| 大表单 | `el-form` + tabs/分组卡片/弹窗，不做一整页字段墙 |
| 弹窗 | `el-dialog`，用于新增、编辑、确认、版本详情、策略结果 |
| 抽屉 | `el-drawer`，用于二级详情、对象详情、调度详情 |
| 过程记录 | `el-timeline`、操作记录表、步骤条 |
| 配置中心 | `el-tabs` + 页内导航 + 配置块 + 日志弹窗 |
| 图标 | Element Plus Icons，图标只辅助识别，不替代关键文字 |

组件使用原则：

- 能用 Element Plus 原生组件表达的，不手写复杂自定义控件。
- Tailwind 主要负责布局、间距、颜色微调和卡片外观，不替代 Element Plus 的表单、表格、弹窗能力。
- 表格列少时不默认 `fixed="right"`；只有列很多且确实需要横向滚动时才固定操作列。
- 单文件 HTML + CDN 原型里，`el-table-column` 必须显式闭合，不写自闭合标签；表格不要再额外包 `overflow-x-auto`，优先让 `el-table` 自己管理列宽和滚动。
- 常规列表表格默认用 `table-layout="fixed"` 保持表头和表体对齐；确实需要自适应宽列时再改为 `auto`，并做实际页面检查。
- 页面级操作放在标题区右侧；行级操作放表格行内；全局操作放顶栏。
- 示例数据要服务于规则表达，不能只是填满页面。

### 2.2 典型页面模板

常见页面优先按这些模板出，不每次重造结构：

| 页面类型 | 默认结构 |
| --- | --- |
| 登录页 | 独立登录布局，不带后台左栏和顶栏；左侧品牌/能力说明，右侧登录表单 |
| 工作台 / Dashboard | 顶部摘要卡 + 待办/提醒 + 关键列表或图块 |
| 列表页 | 标题区 + 筛选区 + 操作区 + 表格 + 分页 |
| 二级详情页 | 返回按钮 + 身份/对象摘要卡 + 关键操作 + tabs 明细/记录/日志 |
| 流程详情页 | 状态摘要 + 操作区 + 分组明细 + 履约/资金/日志/快照弹窗 |
| 新增/下单流程页 | 分组表单 + 选择卡片 + 右侧摘要/费用 + 确认弹窗 + 成功反馈 |
| 弹窗新增/编辑页 | 列表保持上下文，新增/编辑在 `el-dialog` 中完成 |
| 配置页 | 左侧对象/角色列表 + 右侧配置面板或标签页 |

### 2.2.1 后台全页面类型

后续做后台原型时，要先判断页面类型，再选结构，不要只套列表页或表单页。

| 页面类型 | 参考形态 | 必须保留的结构 |
| --- | --- | --- |
| 登录页 | `login.html` | 独立居中或左右分栏；品牌区、登录表单、租户/账号/密码/验证码、记住我、登录反馈 |
| 一级列表页 | 车辆、站点、车组、会员、订单列表 | 标题区在 `main`；筛选区、批量操作、表格、分页、行级操作 |
| 二级详情页 | `member_detail.html` | 返回按钮、身份摘要卡、状态标签、右上操作、指标摘要、tabs 记录表 |
| 流程型详情页 | `order_detail.html` | 状态摘要、主操作/更多操作、客户/订单/资源/费用分组、履约事件、资金记录、审计日志、快照详情 |
| 完整新增流程页 | `new_order.html` | 客户选择、资源选择、服务选择、规则提示、右侧摘要/费用、支付/确认弹窗、成功弹窗 |
| 中型弹窗编辑 | `vehicles.html`、`vehicle_groups.html` | `el-dialog` 约 760-960px；分组表单、图片/上传、保存取消、必要的辅助管理弹窗 |
| 超大弹窗编辑 | `stations.html` | `el-dialog` 约 1180-1280px，`top` 约 3-5vh；分栏/分段表单、地图选点、服务能力、嵌套管理弹窗 |
| 详情抽屉 | 车辆详情、调度详情 | `el-drawer` 约 70%-80%；摘要、tabs、记录表、日志、快捷操作 |
| 配置中心 | 规则、策略、消息、权限 | tabs + 页内导航 + 配置块 + 版本/日志/测试弹窗 |
| 控制台/看板 | 调度、车辆控制台、监控 | 左侧对象或筛选，中间主视图，右侧动作/历史/结果面板 |

页面类型的判定规则：

1. 能在列表上下文内完成的新增/编辑，用弹窗；不要强行跳新页面。
2. 需要连续选择、价格/规则联动、支付确认或成功反馈的，用完整新增流程页。
3. 需要长期查看记录、日志、账户、交易、服务历史的，用二级详情页。
4. 有履约、费用、退款、事故、快照、审计等强过程信息的，用流程型详情页。
5. 登录页永远不用后台主框架；它是授权入口，不是管理页面。
6. 超大弹窗必须分栏或分段，不能把几十个字段堆成单列字段墙。
7. 嵌套弹窗只用于辅助管理、地图选点、上传、版本详情、收付款、风险确认，不要让主流程迷失。

### 2.3 复杂页面组合

从 `vehicle_console`、`system_rules`、`service_products`、`dispatch`、`official_vehicles` 这些页看，复杂后台原型还有几种稳定组合，后续可以直接复用：

| 组合类型 | 适用场景 | 默认结构 |
| --- | --- | --- |
| 控制台页 | 单对象监控、设备控制、实时状态 | 左侧对象列表/筛选 + 中间主视图 + 右侧动作/历史 |
| 规则中心 | 系统规则、策略、推送、AI 配置 | 顶部 tabs + 页内导航 + 可编辑配置块 + 日志/版本弹窗 |
| 调度看板 | 排班、排程、资源冲突、AI 优化 | 筛选区 + 甘特/看板主区 + 抽屉详情 + 策略/结果弹窗 |
| 产品卡片管理 | 产品组、套餐、规则包、版本对比 | 顶部 tabs + 卡片网格 + 编辑弹窗 + 版本详情弹窗 |
| 表格 + 卡片式表单 | 资源台账、企业台账、车辆台账 | 摘要卡筛选 + 列表表格 + tab 化大表单弹窗 |

复杂页的统一处理：

1. 不把所有信息塞进单个表格。
2. 二级详情优先抽屉，不要每次都跳独立页。
3. 大块策略说明、优化结果、日志明细优先弹窗或标签页承载。
4. 摘要卡不只是展示，也可以作为快速过滤入口。
5. 复杂流程页要明确“主视图”是什么，地图、甘特、表格、卡片不能抢中心。

### 2.4 HTML 母版选择

生成 HTML 原型时，优先从 `assets/prototype-templates/` 选择最接近的母版复制后改内容。母版只提供结构、视觉语言和组件基座，不代表业务规则已经确认。

| 用户请求 | 优先母版 |
| --- | --- |
| 登录、授权入口、后台登录页 | `assets/prototype-templates/auth-login.html` |
| 后台基础页面、工作台雏形、通用框架 | `assets/prototype-templates/admin-shell.html` |
| 列表、筛选、表格、批量操作、分页 | `assets/prototype-templates/list-table.html` |
| 独立二级详情、会员/订单/企业/对象详情 | `assets/prototype-templates/detail-page.html` |
| 对象详情、抽屉、时间线、操作记录 | `assets/prototype-templates/detail-drawer.html` |
| 新增流程、下单、开通、配置向导、带摘要确认的录入页 | `assets/prototype-templates/workflow-form.html` |
| 列表页内新增/编辑弹窗、辅助管理弹窗 | `assets/prototype-templates/modal-form.html` |
| 系统规则、策略配置、消息配置、日志 | `assets/prototype-templates/rules-center.html` |
| 调度、排程、监控、控制台、优化结果 | `assets/prototype-templates/operations-board.html` |

使用母版时：

1. 保留统一导航、顶部栏、浅灰底、白色内容模块、蓝色主操作和语义状态色。
2. 替换页面目标、角色、字段、按钮、状态、弹窗和示例数据。
3. 删除不需要的区块，不为了显得完整而保留无意义模块。
4. 如果目标终端不是后台桌面页，先按实际终端重构，不硬套这些母版。

## 3. 交互与状态规范

只做原型也必须把交互讲清楚，至少覆盖：

1. 页面目标：这个页面是看、配、审、查、录入还是处置。
2. 目标角色：谁进入页面，谁能操作，谁只能看。
3. 主动作：一个页面只保留一个最主要的提交动作，其余为次级动作。
4. 字段表达：字段分组、必填、默认值、禁用、说明、联动、示例值。
5. 状态表达：正常、空态、加载、失败、禁用、无权限、风险确认、成功反馈。
6. 列表表达：筛选条件、列字段、批量操作、行操作、分页或滚动方式。
7. 弹窗表达：标题、打开条件、确认/取消、校验失败、提交结果。
8. 抽屉/时间线/步骤条：什么时候展开详情、怎么看过程、什么时候展示阶段进度。
9. 示例数据：用来暴露业务规则，不用无意义 lorem ipsum。

统一动作规则：

- 主按钮位置稳定，文案用动作词，不用“提交一下”“确认处理下”这类虚词。
- 次级按钮优先 `plain` 或 `link`，不要多个主按钮抢焦点。
- 高风险动作必须有确认层和风险提示。
- 页面中的标签、状态、说明文案要和 PRD 术语一致。
- 大表单优先 tabs、卡片分组或分段，不做一屏滚到底的“字段墙”。
- 配置中心优先用 tabs + 分区块，不把所有规则堆在一个长表单里。
- 调度、监控、日志类页面优先保留时间线、记录表或步骤条，不能只有当前状态没有过程。

## 4. Prototype-only 输出要求

如果用户只要原型页，默认仍要一起给出一段短说明，至少包含：

1. 页面目标。
2. 适用角色。
3. 页面结构。
4. 关键字段/按钮。
5. 关键状态/弹窗。
6. 当前假设和未定项。
7. 是否建议同步到 PRD。

如果同模块还没有正式 PRD，原型说明至少要补齐：

- 页面入口。
- 区块结构。
- 字段与按钮。
- 状态与标签。
- 校验与异常提示。
- 权限差异。
- 本期不做。

这样后续就算先做原型，也不会只剩一个“看起来像页面”的空壳。

## 5. 禁止项

- 不把原型写成已经接好接口、已经可上线的真实前端。
- 不为了好看加大量装饰色、营销化视觉或无关动画。
- 不跳过空态、失败态、禁用态、无权限态。
- 不用假数据掩盖规则缺失；缺规则时要标假设或待确认。
- 不在没有确认的情况下，把原型默认同步成真实代码或正式文档。
- 不把新场景原型做成完全不同的风格，除非用户明确给了新模板、新品牌或新终端类型。
