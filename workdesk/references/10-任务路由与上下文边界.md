# 任务路由与上下文边界

本文件只负责判断“该不该读取外部上下文、该读什么、该问什么”。它不维护来源索引，不保存业务事实，不替代正式资料。

## 使用方式

- 日常思考、沟通、总结、判断：回到 `00-工作模式与个人方法.md`。
- 需要文件内容、业务事实、正式资料、写回位置或历史决定：使用本文件做上下文边界判断。
- 需要产出文档、PPT、纪要、验收、交接或知识记录：读取 `30-交付总览.md`，再进入一个窄模块。
- 找不到必要来源时，只问最关键的来源问题，不展开长确认清单。

## 目录

- `1. 什么时候需要外部上下文`
- `2. 上下文选择`
- `3. 最小读取顺序`
- `4. 常见短触发`
- `5. 输出和确认`

## 1. 什么时候需要外部上下文

直接按个人方法层处理：

- 帮我想想、分析一下、拆一下、判断一下、怎么推进、怎么说、怎么回。
- 沟通话术、评审回应、会议纪要结构、周报月报、复盘总结。
- 不依赖具体文件事实的方案结构、PPT 叙事、PRD 草稿、需求拆解。
- Obsidian 个人知识整理建议。

需要读取或确认外部上下文：

- 问题依赖文件内容、业务事实、正式资料、代码、接口、原型、历史决定或写回位置。
- 用户要求修改文件、落正式文档、补版本记录、整理文件夹、写 Obsidian 或同步资料。
- 当前对话中出现互相冲突的事实、版本、路径、名称或口径。
- 输出会被直接用于对外、交付、上线、评审或长期复用。

只出现泛业务词时，不追问来源。先按通用方法给结论；如果无法避免事实判断，再问一个来源问题。

## 2. 上下文选择

判断顺序：

1. 用户本轮直接提供的文字、文件、截图、表格、路径或链接。
2. 用户明确指定的来源、文档名、文件夹、笔记或代码库。
3. 当前对话中已经确认的事实、口径和目标。
4. 最近一次明确选定且仍适用的上下文。

只有一个强信号时，直接使用它。出现冲突时，先指出冲突并问用户以哪个来源为准。

找不到必要来源时，直接问：

> 我需要看哪份文件或哪个文件夹？你把路径发我，我再继续。

如果只是缺少写回位置，问：

> 这次要写到哪里？给我目标文件或目录即可。

用户给出路径后，本轮使用该路径；是否长期记录，另行确认。

## 3. 最小读取顺序

需要读取外部上下文时，只读最少资料：

1. 用户本轮提供的材料。
2. 用户指定的目标文件或入口文件。
3. 与当前任务直接相关的正式文档、版本记录、会议纪要、原型、代码、表格或模板。
4. 必要时再读取同目录的说明、README、索引或历史版本。

不要默认扫全盘、全库、全目录或整套 Obsidian。需要扩大范围时，说明原因和预期收益。

## 4. 常见短触发

用户不需要记命令。自然语言命中以下含义即可触发：

| 说法 | 默认动作 |
| --- | --- |
| 继续 / 接着 / 看看 / 优化 | 沿用最近上下文；恢复不了就问一个关键问题 |
| 帮我想想 / 分析一下 / 拆一下 | 先给结论、影响、待确认和最小动作 |
| 怎么推进 / 下一步 | 给最小推进路径、风险和需要谁确认 |
| 怎么说 / 怎么回 | 先给可直接发送的话，再补内部判断 |
| 写文档 / 写材料 / 写方案 / 做PPT / 写PRD | 判断快答、工作稿还是正式交付；正式交付再走 `30` 对应窄模块 |
| 写纪要 / 总结 / 复盘 | 走会议总结与知识记录模块 |
| 找文件 / 找知识 | 先判断搜索范围；范围不明时问 |
| 记知识 / 存知识 / 双链 | 用户明确要写入时，先检索已有知识，再给写入建议，确认后写 |
| 接手资料 / 整理材料 / 建入口 | 走 `20-事项接入与资料整理.md`，先出方案，不移动文件 |
| 交接 / 收口 | 输出状态、已完成、未决、下一步和写回建议 |
| 优化工作流 / 记规则 | 走 `90-工作流维护与自检.md` |

## 5. 输出和确认

默认输出：

- 简单问题：直接答。
- 有不确定来源：先给基于当前信息的判断，再列最少待确认项。
- 需要正式写文件：先确认目标文件、来源范围、版本记录和同步项。
- 需要整理文件夹或知识库：先给整理方案和影响，再等确认。

最多问 3 个问题，只问会影响方向、事实、写回或长期记忆的问题。

实质工作完成后，只有当某个方法、模板或经验可重复使用、能避免再次出错、能形成检查清单，或用户明确要求记录时，才用一句话提示“这条适合写入知识库”；除非用户确认，不写 Obsidian。
